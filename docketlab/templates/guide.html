What this is

When a federal agency proposes a rule, the public comments on it. The agency is then legally obliged to respond to the significant comments, and it does so in the preamble of the final rule — often hundreds of pages of prose.

Plenty of tools will summarize what the public said. Almost none will tell you what the agency did with it. That's what this does: it pulls the comments, works out what each one actually argued and which provision it attacked, then matches those arguments against the agency's own adjudications and the changes between the proposed and final text.

The output is a ledger: for each submission, whether it drew a response, what the agency said, and whether the rule changed. Aggregate that and you can ask the question nobody has good data on — what kind of comment actually works?

Quickstart

First, the fixture. No keys, no network, about ten seconds. It builds a synthetic docket with problems seeded at known positions and grades the pipeline against them.

  1. Console → Build fixture
  2. Find campaigns → Cluster → Link outcomes
  3. Score fixture — eight checks, and you want eight passes

One of those eight is supposed to read 0%: paraphrase families caught by MinHash. Lexical matching genuinely cannot see a campaign whose members each reworded the sponsor's talking points. That's why the embedding stage exists, and the row below it should read 100%.

Then a real docket.

  1. Settings → paste a regulations.gov key (free at api.data.gov/signup) and an Anthropic key. Test both.
  2. Dockets → pick a starter or search. Hit Check size before pulling anything large.
  3. Pull comments — slow by design, resumable, safe to interrupt.
  4. Find campaigns → Cluster → Load final rule → Diff rule text
  5. Extract arguments → Link outcomes
  6. Ledger to read it, Metrics to measure it, then download the report.

Only steps 5 spend money. Everything else is API quota and CPU.

Finding dockets

Three ways in, depending on whether you already know what you're looking for.

Dockets — you know the ID, or you can search by subject. Always run Check size before pulling: it reports the real comment count, how many API requests that costs, and how much quota you have left.

Watch — you know the sector but not the rulemaking. A profile is an agency set plus a subject filter, and scanning sweeps every matching proposal across the window you choose. It runs on the Federal Register API, which is unmetered, so a twenty-agency sweep costs no regulations.gov quota at all.

Results are classified by what you can do with them, which is the part that saves time:

openThe comment window is still accepting filings. If you have a stake in the rule, this is a deadline, not a research target.
analyzableA final rule exists, so the agency has published its adjudications and the outcome-linkage layer applies. These are the ones worth the full pipeline.
closedThe window shut but no final rule yet — often sitting at OIRA. Only the front half of the pipeline works.

Closing in 30 days sweeps government-wide for comment windows about to shut, ignoring your profiles entirely. Useful as a standing check regardless of what you're analyzing.

The pipeline

StageWhat it doesCostWhat to watch
Pull comments Fetches every comment on the docket plus attachments, extracting text from PDF and Word filings. API quota WITH ATTACHMENTS, not attachment-only — a comment carrying both inline text and a PDF counts as "both", so attachment-only can read zero while extraction is working perfectly.
Find campaigns Exact hashing, then MinHash near-duplicates, then a containment pass that catches form letters with a personal paragraph appended — and separates that paragraph out. free The reduction figure. Zero is correct on a docket with no organized campaign.
Cluster Embeds each analysis unit locally and groups by meaning, catching campaigns that share an argument but no wording. free, CPU The backend name. sentence-transformers is the real path; tfidf-svd is the fallback.
Load final rule Pulls the rule text from the Federal Register and parses the preamble into comment/response pairs. free, no key Pair count and coverage. Low coverage means unknown, not unanswered.
Diff rule text Compares the codified text of the proposal against the final rule, section by section. free, no key Sections found in both documents. Zero means the text markers didn't match this agency's formatting.
Extract arguments For each unit: stance, argument grounds, provisions cited, what it asks for, whether it puts new evidence on the record, and a significance score. tokens Failures should be zero. Tokens per unit tells you what a full docket will cost.
Link outcomes Retrieves candidate responses by embedding, then asks a model whether the passage actually addresses that comment and how it came out. tokens Adjudicated pairs well above the link count — that gap is the model rejecting bad candidates.

Stages are resumable and re-runnable. Dedup, cluster, diff and linkage replace their previous results. Extract arguments skips units it has already done, so re-running after a bigger pull only pays for the new ones.

Reading the ledger

One row per analysis unit — a distinct submission, or one campaign standing for everyone behind it. The Weight column shows how many submissions a row represents.

Sig estimates how likely the agency is to be obliged to respond. Specific, supported, provision-anchored comments score high. A general expression of preference scores low. It is not a measure of whether the comment is right, and it is not a measure of whether you agree.

The response column reads one of three ways:

83147 FR · partial The Federal Register page carrying the agency's response, and how it came out. Accepted means the agency changed the rule or committed to the ask. Partial means it moved some of the way — often conceding the framing while refusing the remedy, which is the most common real outcome. Rejected means it declined and explained.
text changed at §170.17 No written response, but the section this comment cited changed between the proposal and the final rule. The silent grant: agencies rarely write a response to "your text has an error," they just fix it.
no response Nothing matched, and nothing moved. Before reading this as an agency ignoring someone, check two things: whether you pulled the whole docket, and what the preamble parse coverage was.

Click any submitter to see the full submitted text beside the agency's own characterization and its response, so you can judge the match yourself.

Reading the metrics

The four-way grid is the headline. Answered and changed is the strongest evidence an argument landed. Changed only is the silent grant. Neither is the ambiguous cell — it holds both genuine non-engagement and comments whose response you simply haven't pulled yet.

Response rate by significance is a test of the process itself. If notice-and-comment works as designed, the curve rises — a well-argued, provision-anchored submission should be far likelier to draw a reply than a form letter.

Which grounds move the agency is the practical one. It crosses argument type against outcome, so you can see whether cost objections, statutory authority challenges, or plain technical corrections fare differently. This is the table that turns into advice about how to write a comment that lands.

Watch the base rate on silent grants. If nearly every section of a rule changed between proposal and final — which happens, some rules are rewritten wholesale — then "the section this comment cited changed" is true of almost everyone and tells you nothing on its own. The page says so when that happens, and falls back to counting only sections that moved substantially more than the rest of the rule, each shown with its magnitude.

Orphan responses are agency adjudications matching no comment you hold. On a partial pull that's expected. On a complete one it means either the parser found pairs that aren't really there, or the agency was responding to comments filed outside this docket.

Anything computed over fewer than thirty units is labelled indicative only and under ten as too few to read as a rate. Those labels are not decoration — a response rate over six comments is noise with a percent sign on it.

The report

Metrics → Download report produces a single HTML file with every chart, the full ledger, and — deliberately — a methodology section and a limits section.

No external assets and no network calls, so it opens on any machine and prints cleanly. The limits section travels with the numbers on purpose: a response rate quoted without its parse coverage and corpus completeness is a figure someone will repeat in a room where you aren't present to caveat it.

Quota and cost

Two different meters, and only one of them charges you money.

regulations.gov quota is the one that actually constrains you. A free key allows 1,000 requests an hour, and comment text costs one request per comment — so a 40,000-comment docket is roughly 40 hours of quota, not 40 minutes of waiting. The Usage tab reads the remaining count from the server's own response header rather than a local tally, so it stays right even if you've used the key elsewhere. Pulls are resumable: run out, wait for the reset, press the same button.

Token spend comes only from Extract arguments and the adjudication half of Link outcomes. Everything else — pulling, campaign detection, clustering, the Federal Register fetch, the text diff — is free.

The projection is built from this docket, not a generic rate. Once you've analyzed anything, Usage knows the real cost per unit and extrapolates from the observed collapse ratio. That matters because the two things driving the bill — how much a docket collapses under dedup, and how long its comments run — vary enormously. A campaign-heavy docket of 40,000 can be cheaper to analyze than a technical one of 400, because 39,000 of those comments are the same letter.

Prices are editable on the Usage tab. Published rates change, and a stale hardcoded figure quietly misstating your costs is worse than no figure at all.

Doctrine

  • Zero custody. Everything runs on your machine. The corpus, the keys, and the analysis never leave it — there is no server to send them to.
  • Absent is not zero. An unparsed preamble is unknown, not unanswered. The interface says so wherever the distinction matters.
  • Collapsing is display, never deletion. Campaign members keep their own rows and counts always report true submission numbers. A campaign of 40,000 is a real political fact even when it contributes one argument.
  • Everything walks back. Every figure traces to a comment ID, and every comment ID traces to a document on regulations.gov.
  • Raw stays raw. API payloads are written verbatim and never edited. Derived tables can always be rebuilt.
  • Two channels, not one. A comment succeeds by drawing a response or by getting the text quietly fixed. Scoring only the first misreads the second as failure.
  • Not sentiment. "73% opposed" is the least useful sentence you can write about a docket. An agency isn't taking a vote.

Troubleshooting

SymptomWhat's happening
Buttons greyed outA stage is running. Only one runs at a time; the page reloads itself when it finishes.
Nothing in the log for minutesNormal during a pull. Ingest self-throttles to about 3.8 seconds per comment to stay under the hourly limit, and only reports every 25.
How much will this cost?Usage tab. Analyze a sample first, then enter the docket's full comment count and press Project.
"quota exhausted"You've spent 1,000 requests this hour. Progress is saved — wait for the reset and press the same button; it resumes.
Port already in use / error 10013Windows has reserved the port. Set DL_PORT in the launcher to something else and relaunch.
embeddings: noneCosmetic — the backend isn't resolved until something embeds. Run Cluster and it fills in.
Backend says tfidf-svdsentence-transformers isn't installed or its model didn't download. Everything still works, but matching is weaker. pip install sentence-transformers
Analysis stage refuses to runNo Anthropic key saved. Everything except Extract arguments and the adjudication half of Link outcomes runs without one.
Zero comment/response pairsThat agency organizes its preamble thematically instead of as Comment/Response pairs. The parser reports which convention it tried; treat a low coverage figure as unknown.
Need to query while it's running? python -m docketlab inspect tables, inspect diff, inspect quota, or sql "SELECT ...". These open the database read-only, so they work without stopping the console.
Did I lose my work?No. Everything is on disk under {{ home }} as it happens. Only the on-screen log is in memory.

Glossary

Docket
The folder holding everything about one rulemaking, including every public comment. IDs look like AGENCY-YYYY-NNNN.
NPRM
Notice of Proposed Rulemaking — the proposal people comment on.
Preamble
The explanatory prose at the front of a rule. In a final rule it contains the agency's responses to comments. It is not the regulation itself.
Codified text
The actual regulation — the numbered sections that end up in the CFR. What the diff stage compares.
Provision
A specific section a comment attacks, like 170.14(c)(4). The join key that makes outcome measurement possible, which is why extraction is strict about the format.
Analysis unit
What gets analyzed: a distinct submission, or one exemplar standing for a whole campaign.
Campaign
A family of identical or near-identical submissions, usually organized by an advocacy group.
Personal insert
The bit a campaign participant wrote themselves. Real content the template didn't supply, and the most commonly discarded signal in comment analysis.
Significance
An estimate of how likely the agency is to be obliged to respond — not a measure of merit.
Silent grant
The agency changed the text a comment asked about without writing a response to it.
Analysis unit cost
What one unit costs to extract and link. The number the whole projection hangs on, measured rather than assumed.
Collapse ratio
The share of submissions dedup folds into campaigns. The single biggest lever on what a docket costs.
Orphan response
An agency adjudication matching no comment in your corpus.

What it can't tell you

Whether a comment caused a change. A section moving after a comment cited it is evidence, not proof. Agencies change text for many reasons, including comments that aren't in your corpus at all.

Why a comment went unanswered. Three different things produce the same red stamp: the agency didn't engage, the response sits in the part of the preamble the parser missed, or the agency acted without writing about it. The diff stage separates the third. The first two need you to check coverage.

Whether the machine judgements are right. Argument types, significance, and verdicts are model output. They're reproducible and every one cites a comment ID and a Federal Register page — which means they're checkable, and worth checking before you quote them.

Whether the parser handles your agency. It has been verified against DoD, whose preambles use plain Comment/Response pairs. Three conventions are recognized and there are certainly more. The parse line from Load final rule reports which matched and what fraction of the preamble it covered — a low number means unknown, not unanswered.

That linkage is exactly reproducible. Retrieval proposes candidates and a model adjudicates each pair on its own, so a borderline match can fall either way between runs. Aggregate rates hold steady; one borderline row may not. Open the comment and read the agency's response beside the submitted text when a specific linkage matters.

Anything about a docket you only partly pulled. This is the most common way to be misled here. Response rates and unanswered lists are only meaningful against a complete corpus. The orphan-response count on the Metrics page is the fastest way to see how far off you are.
